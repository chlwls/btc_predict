# 업비트 자동매매 (V6 MULTI_TREND)

모의매매와 **같은 고정 전략**(`paper_trading/strategy_frozen.py`, `portfolio_frozen.py`)을 업비트 원화 마켓에서 매매한다.
- 신호: Binance USDT 1시간봉 (전략을 검증한 데이터)
- 주문: 업비트 원화 마켓 시장가
- 업비트 원화 마켓에 없는 코인의 몫은 현금으로 둔다 (실행할 때 출력됨)

## 안전장치
| 장치 | 내용 |
|---|---|
| 기본값은 dry run | `--live`를 붙이지 않으면 주문 없이 계획만 출력한다 |
| 투자 한도 | `config.json`의 `capital_cap_krw`보다 많이 운용하지 않는다 |
| 킬 스위치 | 운용 자산이 최고점 대비 36% 하락하면 모든 매매를 멈춘다. `live_state.json`에서 `"halted": true`를 지워야 다시 시작한다 |
| 하루 1회 | 같은 판단 시점에는 한 번만 매매한다 (`--force`로 재실행 가능) |
| 오래된 데이터 차단 | 시세 데이터가 판단 시점보다 6시간 넘게 지났으면 매매하지 않는다 |
| 최소 주문 | 5,000원 미만 주문은 하지 않는다. 목표와 차이가 1칸(한도/10)의 10% 미만이면 매매하지 않는다 |

## 준비 (한 번만)
1. 패키지 설치: `python -m pip install pyjwt pandas numpy requests`
2. 업비트 → 마이페이지 → Open API 관리에서 키 발급
   - 권한은 **자산조회, 주문조회, 주문하기**만. **출금은 절대 체크하지 않는다**
   - 허용 IP에 본인 PC의 공인 IP를 등록한다 (집 IP가 바뀌면 다시 등록)
3. `upbit_keys.env.example`을 복사해 `upbit_keys.env`를 만들고 키를 넣는다
   (git에 올라가지 않는다. 채팅에도 붙여넣지 말 것)

## 단계별 시작 계획
| 단계 | 기간 | 실행 | `config.json` 한도 | 다음 단계 조건 |
|---|---|---|---|---|
| 1 | 2~4주 | `python live_trade.py` (dry run). 출력된 주문을 **업비트 앱에서 직접** 넣는다 | 500000 | 계산이 매번 상식적이고 실제 체결이 계획과 맞음 |
| 2 | 2주 | `python live_trade.py --live` 자동 주문. 매일 업비트 앱으로 체결 확인 | **100000** | 주문 오류 0건, 체결이 계획과 일치 |
| 3 | 이후 | `run_live.bat`에 `--live`를 붙여 작업 스케줄러로 자동 실행 | 500000 | 킬 스위치에 걸리지 않음 |

1단계에서 직접 주문할 때는 봇이 잔고를 읽어 계획을 세우므로, 다음 날 실행 전에 주문을 끝내 둔다.

## 매일 자동 실행 (3단계)
```
schtasks /Create /F /SC DAILY /ST 10:20 /TN BTC_Live /TR "C:\Users\M\Desktop\btc_predict\live_trading\run_live.bat"
```
`run_live.bat`의 `python live_trade.py` 뒤에 ` --live`를 붙여야 실제 주문이 나간다.

## 주의
- 봇은 이 계정의 원화(한도까지)와 대상 코인 잔고를 **전부 자기 것으로 본다**. 같은 계정에서 이 코인들을 따로 사고팔지 말 것
- 신호는 Binance 가격, 체결은 업비트 원화 가격이라 김치 프리미엄이나 환율에 따라 결과가 조금 다를 수 있다
- 업비트 수수료 0.05%는 백테스트 가정(0.15~0.20%)보다 낮다
- 이 코드는 업비트 실제 API에 연결해 시험하지 못했다(개발 환경에서 접속 차단). 주문 로직은 가짜 거래소로 300일 시뮬레이션해 검증했다
- 기록: `live_log.csv`(주문), `live_console.log`(실행 출력), `live_state.json`(상태)
